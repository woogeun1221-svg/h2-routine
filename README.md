# H2 강제 루틴 트래커

매일 지켜야 하는 강제 루틴 5개(푸쉬업, 턱걸이, 독서, 가슴 펴기, 송은)와 주간 항목 2개(투자 원칙 검토, 손익비 스냅샷), 그리고 맨 위의 하루 만족도 질문
"스스로에게 만족할만한 하루를 보냈는가? — 컨트롤 할 수 있는 건 오로지 나뿐"(O/X, X면 사유)을 기록하는 1인용 PWA.
정상 포지션 / 최소 포지션 2단계 + **"두 번 연속 거르지 않는다"** 룰. v2(2026-11-08)부터 평일 정상에는 주간 시간표의 운동 슬롯이 필요하다.

하단 탭(아이콘): 오늘, 시간표, 추이, 헬스, 설정. 2026-11-08 디자인 개편: 시스템 글꼴(iOS SF와 Apple SD 산돌고딕 Neo, 숫자는 고정폭 숫자),
면 대비와 헤어라인 위주의 토큰(`src/styles.css` 맨 위), 색 규칙은 그대로. 헬스 탭(Iron)은 자체 스타일 그대로다.

## 주간 운동 시간표 (v2, 2026-11-08)

`routine-v2.html`(v2 프로토타입, 참조 보존)의 시간표 로직을 운영 앱에 얹었다. 루틴 구성은 그대로고 운동 슬롯은 평일 정상 조건으로만 더한다.

- 평일(월~금)마다 슬롯 하나: 아침 / 점심 / 저녁런닝. 주 단위 계획이고 키는 그 주 월요일 날짜. 계획이 없는 주는 그 전 가장 가까운 주의 슬롯을 물려받고,
  그것도 없으면 전부 아침. 요일마다 메모 한 칸(송은 일정용, 물려받지 않음). 처음 손대는 주는 물려받던 슬롯을 복사해 그 주 계획으로 저장한다.
- 토일은 시간표가 없다(송은 시간). 운동 기록은 남길 수 있지만 판정에는 영향이 없다.
- 시간표 탭(2026-11-08 다시 설계): 위에 `일간 | 주간` 전환(이 기기 편의 설정 `h2-routine-plan-mode`, 기본 주간).
  - 주간: 이번 주 / 다음 주(ISO 주차와 날짜 범위). 요일 열 x 아침(~10시), 점심(~14시), 저녁(~21시) 칸의 시간표. 평일 칸을 누르면 그날 계획이 그 칸으로 옮겨 간다.
    블록 상태는 계획(빨강 테두리), 완료(빨강 채움), 비었음(지난 날, 오늘은 컷오프가 지나면 '지남', 빗금), 옮김(계획 칸, 실제는 다른 칸에서 함, 점선).
    토일 열은 송은 시간 한 덩어리(기록한 운동이 있으면 그 칸에 완료 블록). 지난 날 머리 아래 그날 포지션 막대(빨강, 황동, 파랑). 오늘 열은 빨강 머리.
    아래에 평일 메모 다섯 줄과 "아침 n, 점심 n, 저녁런닝 n" 집계. 날짜 머리를 누르면 그날 일간 보기.
  - 일간: 이번 주 월요일부터 다음 주 일요일까지 ‹ › 로 하루씩. 06~24시 시간축 위에 슬롯 창(06~10, 12~14, 18~21시, `SLOT_WINDOW`), 23시 취침 점선,
    오늘이면 한국 시간 지금 선. 블록을 누르면 그날 계획이 바뀐다. 그날 메모, 그날 포지션과 슬롯 안내가 함께 나온다.
  - 토일에 열면 다음 주가 기본이고, 자정이 지나면 기본 주와 일간 날짜도 새 날짜로 다시 정한다. 1분마다 칸과 시간축만 다시 그린다(메모 입력 보존).
- 오늘 화면: 운동 슬롯 블록(06~24시 하루 막대에 슬롯 창, 계획 칸, 지금 위치, 23시 취침. 아래 버튼에 '계획' 배지, 실제로 한 슬롯을 누르면 완료,
  다시 누르면 취소, 계획과 다르면 "계획 아침 → 실제 점심").
  시간 경과 안내는 한국 시간 기준이고 1분마다, 앱을 다시 열 때마다 갱신한다(슬롯 블록만 다시 그려 입력 중인 칸을 건드리지 않는다).
  계획 슬롯이 지나면 아직 시각이 남은 뒷 슬롯이 백업이다: 아침 10시 지남 → "백업 순서: 점심 → 퇴근 런닝", 점심 14시(또는 아침 계획이 14시를 넘김) → "백업: 퇴근 런닝",
  21시 지남 → "최소 포지션(푸쉬업, 턱걸이)으로 마감". 블록 아래 현재 포지션 pill과 "정상까지"(미달이면 "최소까지"를 먼저).
- 판정: 정상 = 기존 정상 조건 + 평일 운동 슬롯. 최소와 미달은 그대로(슬롯은 미달을 만들지 않아 스트릭에 영향이 없다).
  활성일 `exerciseSlotStart`(업데이트 후 처음 연 날)부터 판정해 지난 평일 정상을 소급해 최소로 바꾸지 않는다. 그 전 날짜를 볼 때는 슬롯 블록을 숨긴다.
- 배너: 어제 미달이면 "어제 미달.", 그제도 미달이면 "이틀 연속 미달.".
- 추이: 캘린더는 월요일 시작, 토일 라벨은 황동. 월별 장부(확정일 기준, 오늘 제외)에 `슬롯` n/N(슬롯을 한 평일 / 슬롯 조건이 있던 평일)과 `송은 X` 열.
- 날짜 옆 `W45` 같은 ISO 주차(노션 플래너와 같은 번호, 2026-11-09 = W46).
- 메모는 이 기기 localStorage에만 있다. 슬롯 계획은 메인컨트롤 봇 동기화로 알림 서버와 주고받는다(아래 '메인컨트롤 봇과 주고받기').

## 메인컨트롤 봇과 주고받기 (2026-11-08)

알림에 연결된 기기(설정의 연결 코드)는 시간표 슬롯과 오늘 포지션을 메인컨트롤 봇(텔레그램 WOOGEUN_BOT DM)과 주고받는다.

- 봇 DM 명령(alphasense 웹훅 → `alphasense/routine_bridge.py` → `scripts/reminder_service.py bot` → `scripts/routine_bot.py`):
  `/오늘`(또는 `/루틴`) 오늘 포지션, 운동 슬롯 안내, 정상까지와 최소까지, 어제 포지션. `/시간표` 이번 주(토일엔 다음 주), `/시간표 다음`, `/시간표 이번`.
  `/슬롯 화 점심` 계획 바꾸기(여러 개 `/슬롯 월 아침 수 저녁`, 붙여 쓰기 `화점심`, 다음 주 `/슬롯 다음 화 점심`). 토일과 모르는 단어는 사용법으로 답한다.
  영문 별칭 `/routine`, `/plan`, `/slot`. 메인컨트롤 DM 밖에서는 안내만 한다.
- 앱 → 서버: `POST /state`(Bearer 기기 인증). 오늘과 어제 요약(포지션, 남은 항목 문구, 계획 슬롯과 실제 슬롯, 송은 X 여부),
  이번 주와 다음 주 계획 슬롯(물려받은 계획은 u=0), 지난주부터 4주 뒤까지 직접 저장한 주의 계획 슬롯, 슬롯 조건 시작일.
  **메모, 하루 만족도 O/X와 사유, 수치 원본은 보내지 않는다.** 보내는 때는 기존 알림 보고와 같다(수치가 바뀌면 1.5초 뒤, 앱을 숨길 때, 화면이 켜진 동안 1분마다, 앱을 열 때).
- 서버 → 앱: 같은 응답에 지난주부터의 서버 계획이 온다. 계획은 주 단위로 마지막 수정이 이긴다(`plans[월요일].u`, 밀리초).
  봇의 `/슬롯`은 u=지금으로 쓰므로 앱이 다음 동기화 때 받아 슬롯만 바꾸고 메모는 이 기기 것을 둔다. 같은 u면 앱이 보낸 것으로 바꾼다(물려받은 계획 갱신).
  iOS 홈 화면 앱은 닫혀 있는 동안 받을 수 없어 **봇에서 바꾼 계획은 앱을 열 때 들어온다**. 입력 중이면 저장만 하고 다음 렌더 때 보인다.
- 일요일 20시 다음 주 시간표(`reminder_service.py weekly`, launchd `com.woogeun.routine.weekly`): 연결된 기기가 있고 최근 14일 안에 앱 요약이 들어왔을 때만,
  같은 날 한 번. `--dry-run`. 설치는 `cp launchd/com.woogeun.routine.weekly.plist ~/Library/LaunchAgents/ && launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.woogeun.routine.weekly.plist`.
- 루틴 알림(푸시, 봇 대체 발송) 끝에 오늘 계획 슬롯이 아직 열려 있으면 "운동 슬롯은 점심, 14시까지." 한 줄이 붙는다(슬롯 조건 시작일부터 평일, 아직 안 했을 때).
- 설정 화면 알림 칸에 "메인컨트롤 봇과 동기화됨 HH:MM" 줄.

- 손익비 스냅샷(2026-10-29 추가)은 포트폴리오 손익비 대시보드에서 주 1회 스냅샷을 찍는 주간 항목이다. 투자 원칙과 같은 주간 규칙(월요일 시작, 어느 날이든 완료,
  금요일까지 미완료면 그 금요일 미달, 주말 완료는 추이에서 최소)을 따르지만 완전히 독립이다. 활성일 `rrSnapshotStart`부터 판정하고 완료일은 `rr: true`.
  카드의 "대시보드 열기"는 https://macmini.taile484c7.ts.net/rr/ 로 간다(토큰 로그인은 그쪽). 주간 항목 정의는 `WEEKLIES`(`src/logic.js`)에 데이터로 추가한다.
- 가슴 펴기(2026-11-03 추가)는 "가슴을 당당히 펴고 있는가"를 하루 한 번 O/X로 답하는 일간 체크 항목이다. O여야 그날 통과이고
  X나 미응답은 그날 미달이다(송은과 달리 해당없음이 없다). 활성일 `postureStart`(업데이트 후 처음 연 날)부터 판정하고 그 전 날짜는 소급하지 않는다.
  기록은 `c: "o" | "x" | null`. 설정 목표치에는 없고, 습관별 추이에는 O 일수가 정상, 나머지가 미달인 행으로 나온다.
  체크 항목 정의는 `CHECKS`(`src/logic.js`)에 데이터로 추가한다. 루틴 알림은 `statusOf`를 따르므로 미응답이면 재촉이 온다.
- 푸쉬업 단계 버튼은 +5, +10, +25 (2026-10-29). 목표(정상 100, 최소 30)는 그대로다.
- 스쿼트는 2026-10-29 은퇴. 업데이트 후 처음 연 날(`squatEnd`)부터 판정에서 빠지고, 그 전 날짜는 스쿼트 포함 기준 그대로다
  (턱걸이 활성일의 거울 규칙, 소급 없음). 정의는 `HABITS`에 남아 있어 옛 기록의 `s`와 `settings.s`가 검증을 통과한다.
  습관별 추이의 스쿼트 행은 종료일 전 표본이 있는 달에만 남는다. 설정 목표치에는 안 나온다. 헬스 탭 하체 프로그램의 스쿼트는 별개(그대로).
- 과거 날짜 수정(2026-10-29): 오늘 화면 날짜 옆 ◀ ▶ 또는 14일 스트립 칸을 누르면 그날 기록으로 이동한다(시작일~오늘).
  카드, 가슴 펴기, 송은, 투자 원칙, 만족도 O/X가 모두 그날에 쓰이고, 카드 목록은 그날 활성이던 습관(은퇴 전 스쿼트 등)이다.
  연속 생존, 이달 정상, 어제 미달 배너는 계속 오늘 기준. 자정이 지나거나 가져오기, 초기화를 하면 오늘로 돌아온다.
  되돌리기(↺) 스택은 날짜를 옮길 때 비운다. 만족도 응답의 알림 서버 전송은 7일 이내 날짜만 받고 그 밖은 조용히 무시한다.

- 투자 원칙은 매주 한 번 정독하고 검토한다. 어느 요일이든 체크할 수 있고 목요일이나 금요일을 권장하며, 금요일까지 미완료면 그 금요일이 미달이다. 주말의 늦은 완료는 기록하되 이미 지난 금요일 판정을 소급 변경하지 않는다.
- 주간 루틴은 기능을 처음 연 날부터 적용해 기존 일간 기록을 소급 변경하지 않는다.
- 턱걸이(정상 20회, 최소 5회)는 2026-10-19 추가. 업데이트 후 처음 연 날(`pullupStart`)부터 판정에 들어가고, 그 전 날짜는 세 습관 기준 그대로다. 습관별 추이의 턱걸이 행도 그날부터 센다.
- 습관별 추이의 `투자 원칙(주)` 행은 금요일까지 완료=정상, 주말 완료=최소, 일요일까지 미완료=미달로 집계한다. 주간은 금요일이 속한 달에 귀속한다.

- 색 컨벤션(국장식): 빨강=정상(달성), 황동=최소, 파랑=미달
- 기록 원본은 기기 localStorage에만 있다. 알림 서버는 아래 알림 보고와 봇 동기화 요약만 받는다. 백업은 [데이터 내보내기] JSON.
- 가져오기(v2부터)는 **합치기**: 같은 날짜는 가져온 기록으로 덮어쓰되 가져온 쪽에 없는 항목(만족도 사유 등)은 남기고, 시작일과 활성일, 종료일은 더 이른 쪽,
  같은 주 계획은 가져온 계획으로 바꾼다. 목표치는 가져온 파일에 `settings`가 있을 때만 따른다. v1 내보내기, v2 백업, routine-v2 프로토타입 JSON(`targets`는 버림)을 받는다.
  통째로 바꾸려면 기록 초기화 뒤 가져온다. 기록 초기화는 2단계(기록 초기화 → 정말 전부 삭제 / 취소).
- `h2-routine-tracker.html` = v1 프로토타입 (Claude.ai 아티팩트용, 참조 보존)

## 알림 (앱 푸시 2026-10-30 추가, 메인컨트롤 봇 2026-09-17)

종류는 둘, 한국 시간, 어느 기기도 충족을 보고하지 않았을 때만. 시각은 `SCHEDULE`(`scripts/reminder_service.py`)과 launchd plist 가 같이 정한다.

- 루틴 미달(2026-11-03부터 두 시간마다): 오전 9시부터 밤 9시까지 두 시간마다, 오늘 판정이 미달(`statusOf` = miss, 금요일엔 주간 항목 포함)이면 슬롯마다 한 번.
  낮 슬롯 문구는 "가슴을 당당히 펴고 있는가?"로 시작하고 밤 9시는 자기 전 마지막 재촉. 금요일엔 투자 원칙 검토와 손익비 스냅샷 마감 문구가 붙는다.
  같은 tag 라 폰에는 최신 알림 하나만 남는다. 어느 기기가 최소 포지션 이상을 보고하면 다음 슬롯부터 멈추고, 다시 미달로 돌아가면 다시 온다.
- 밤 11시 만족도 미응답: 하루 만족도 O/X를 안 골랐으면.

전달 경로: 연결된 기기에 푸시 구독이 하나라도 있으면 Web Push(iOS 16.4 이상 홈 화면 앱, 데스크톱 브라우저). 구독이 없거나 전부 실패하면
밤 9시와 11시(`BOT_HOURS`)만 메인컨트롤 봇 DM(기존 `../_core/tg-notify`)으로 넘어가고, 낮 슬롯은 건너뛴다(봇은 하루 두 번 유지).
404, 410으로 끊긴 구독은 지운다. 429나 네트워크 오류는 구독을 남긴다.

연결은 폰에서 한 번: `python3 scripts/reminder_service.py pair`가 7일짜리 일회용 코드를 메인컨트롤 DM으로 보낸다.
홈 화면 H2 루틴 앱 → 설정 → 알림 칸에 붙여넣고 **연결하고 알림 켜기** 한 번(알림 권한 요청, 구독, 연결을 같이 한다).
Safari 탭이나 알림 미지원 브라우저에선 연결만 되고 봇이 알린다. 이미 연결된 기기는 **이 기기 알림 켜기 / 끄기**. 권한을 거부했으면 iOS 설정의 알림에서 허용한 뒤 다시 켠다.

앱이 서버에 보내는 것: 날짜, 만족도 응답 여부, 루틴이 최소 포지션 이상인지(둘 다 불리언), 브라우저가 만든 푸시 구독(엔드포인트, 공개키, 인증 비밀),
그리고 2026-11-08부터 메인컨트롤 봇 동기화 요약(위 '메인컨트롤 봇과 주고받기'). O/X 값, 사유, 메모, 운동 수치 원본은 보내지 않는다.
수치가 바뀌면 1.5초 뒤, 앱을 숨길 때, 화면이 켜진 동안 1분마다 동기화한다.

- 클라이언트: `src/push.js`(구독, 상태 문구), `src/reminders.js`(연결, 보고 큐, `syncState`), `src/botsync.js`(봇 동기화 요약과 계획 적용 규칙),
  `public/push-sw.js`(푸시 수신과 알림 표시, 앱 배지).
  생성된 `dist/sw.js`가 `importScripts('push-sw.js')`로 불러온다(`vite.config.js` workbox.importScripts). 앱을 열면 배지를 지운다.
- 서버: `scripts/reminder_service.py serve`(localhost:8815, Funnel `/routine-api`). `GET /push/key`, `POST /pair {code, subscription?}`,
  `POST /answer {day, answered, routine?}`, `POST /push/subscribe {subscription}`, `POST /push/unsubscribe {endpoint}`,
  `POST /state {today, days, plans, slotStart}` → `{ok, plans}`(마지막 넷은 Bearer 기기 인증, `/state` 검증은 `parse_state`).
  DB `data/reminders.sqlite3`(git 제외, 0600): `subscriptions`, `answers.routine`, `reminders(day, kind, slot)`, `plans`, `summaries`, `meta`(슬롯 시작일).
  옛 스키마는 열 때 자동 이행, 새 표는 없으면 만든다. `bot`(표준입력 명령 → ASCII JSON `{reply}`), `weekly [--dry-run]`.
- 발송기: `scripts/web_push.cjs`. 외부 패키지 없이 Node 내장 crypto로 RFC 8291(aes128gcm)과 RFC 8292(VAPID ES256)를 구현했고
  `test/web-push.test.js`가 RFC 8291 검증 벡터와 바이트 단위로 비교한다. VAPID 키는 `data/vapid.json`(0600), 서비스가 처음 뜰 때 `keygen`으로 만든다.
  Node는 `/opt/homebrew/bin/node` 절대경로(launchd의 PATH에 homebrew가 없다).
  **`data/vapid.json`은 지우거나 다시 만들지 않는다.** 이 키가 바뀌면 기존 구독 전부가 403으로 실패하고(404, 410이 아니라 정리도 안 된다) 매일 봇 폴백으로만 간다.
  잃어버렸다면 폰에서 알림 끄기 뒤 켜기로 새 키에 다시 구독해야 한다.
- launchd `com.woogeun.routine.reminder`: 21:00과 23:00에 `remind`(시각으로 종류를 정한다. `--kind routine|reflection`, `--dry-run`).
  `status`는 기기 수, 오늘 보고, 구독 수. `push-test`는 연결된 구독 전부에 확인 알림을 보낸다.
- iOS 주의: 알림은 홈 화면에 추가한 앱에서만 켤 수 있고, 권한 요청은 탭 핸들러 안에서만 열린다. 모든 푸시는 알림을 띄운다(조용한 푸시가 쌓이면 iOS가 구독을 끊는다).
  앱을 홈 화면에서 지우면 구독도 사라진다(다음 발송 때 410으로 정리).

## 헬스 탭 (Iron Terminal 통합, 2026-10-13)

상체/하체 근력운동 트래커 Iron Terminal(React 19 + TypeScript)을 `헬스` 탭으로 품었다.
소스는 `src/iron/`(domain, storage, ui), 테스트는 `test/iron/`. 탭을 처음 열 때 `src/iron/mount.tsx`를
동적 import 해 `#screen-iron`에 마운트하므로 초기 번들은 루틴 그대로다. 청크는 서비스워커 프리캐시 목록에 들어가지만(`dist/sw.js`), 오프라인 동작은 QA 가 SW 를 차단하므로 실기기에서 확인한다.

- Iron 의 전역 CSS(`:root`/`body`/`button`/`input`…)는 빌드 시 `.iron-root` 아래로만 접두사 처리된다
  (`vite.config.js`의 postcss-prefix-selector). 루틴 화면의 토큰과 버튼은 영향을 받지 않는다.
- embedded 모드: Iron 의 하단 네비, 설치 안내, SW 갱신 토스트는 끄고, 헤더 아래 보조 메뉴(홈/차트/기록/히스토리/캘린더)로 대체.
- 세트 수 조정(`src/iron/domain/sets.ts`): 기록 화면에서 종목마다 ＋ 세트 추가 / × 삭제(1~12). 다음 기록은 마지막에 실제로 한 세트 수로
  시작하고, 설정 → 기본 세트 수에서 종목별 출발값을 바꾼다. 증량 신호는 그날 기록한 세트 전부가 목표 횟수를 넘겼는지로 본다.
- 저장 키는 Iron 그대로 `ironterminal:v1`. 루틴 기록 `h2-routine-v1`과 섞이지 않으며 백업도 각자 화면에서 한다.
- **기존 기록 이사(한 번만)**: 예전 주소 `/iron/` 맨 위 배너의 **이사 코드 복사** → 홈 화면 `H2 루틴` → 헬스 → 설정 → **이사 코드 붙여넣기** → 가져오기.
  코드는 `IRONMOVE1.gz.…`(gzip+base64url, `src/iron/storage/transfer.ts`)이고 기기 밖으로 나가지 않는다. 현재 기록이 있으면 교체 전에 확인하고 자동 백업한다.
  Safari 탭과 데스크톱에서는 배너의 **새 앱으로 이동**이 `#iron-import=<코드>` 해시로 한 번에 넘긴다(iOS 홈 화면 PWA 는 Safari 와 저장소가 분리돼 이 경로가 닿지 않는다).
  예전 방식(JSON 파일 내보내기/가져오기)도 그대로 된다.
- 원본 `~/projects/iron-terminal/`과 launchd `com.woogeun.ironterminal.serve`는 이사 확인 전까지 유지한다.

## 데이터 스키마 v2 (v1 호환)

저장 키는 그대로 `h2-routine-v1`이다. v2 이행은 필드를 덧붙이기만 한다(`v`, `exerciseSlotStart`, 그리고 쓰기 시작하면 `e`, `plans`).

```json
{ "v": 2,
  "startDate": "YYYY-MM-DD",
  "investmentReviewStart": "YYYY-MM-DD",
  "rrSnapshotStart": "YYYY-MM-DD",
  "pullupStart": "YYYY-MM-DD",
  "squatEnd": "YYYY-MM-DD",
  "postureStart": "YYYY-MM-DD",
  "exerciseSlotStart": "YYYY-MM-DD",
  "days": { "YYYY-MM-DD": { "p": 0, "s": 0, "t": 0, "r": 0, "w": null, "c": "o", "i": true, "rr": true, "e": "noon", "self": "o", "selfReason": "" } },
  "plans": { "YYYY-MM-DD(월요일)": { "1": "am", "2": "noon", "3": "run", "4": "am", "5": "am", "m1": "메모" } },
  "settings": { "p": { "target": 100, "min": 30 } } }
```

`p` 푸쉬업(회), `s` 스쿼트(회, `squatEnd` 전 날짜만 판정), `t` 턱걸이(회, 없으면 0), `r` 독서(분), `w` 송은(`"o"` | `"x"` | `null`=해당없음), `c` 가슴 펴기(`"o"` | `"x"` | `null`=미응답, `postureStart`부터 O여야 통과), `i` 투자 원칙 검토 완료(`true`, 완료한 요일에 사용), `rr` 손익비 스냅샷 완료(`true`, 같은 방식), `e` 그날 실제로 한 운동 슬롯(`"am"` | `"noon"` | `"run"` | `null`, `exerciseSlotStart`부터 평일 정상 조건), `self` 하루 만족도(`"o"` | `"x"` | 없음=미응답), `selfReason` X 사유.
`plans`는 그 주 월요일 날짜가 키이고 `1`~`5`가 월~금 슬롯, `m1`~`m5`가 메모(500자 이하)다. 활성일, 종료일 필드가 없으면 처음 연 날로 채운다. `v`는 없거나 1, 2만 받는다.
